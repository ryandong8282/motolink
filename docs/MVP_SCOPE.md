# MotoLink 首期 MVP 范围

## 目标

用最小成本验证四个核心假设：

1. 摩友是否愿意临时创建 / 加入车队；
2. “按住说话、松手释放”的半双工交互是否适合骑行；
3. 腾讯 TRTC 的前台手机纯音频是否能满足基础对讲；
4. 队内实时位置和掉队提示是否具备实际价值。

## 本次实现

### 小程序

- 开发态登录；
- 当前定位、附近车友列表与地图标记；
- 创建车队、使用 6 位房间码加入；
- 车队成员展示；
- WebSocket 连接状态；
- 腾讯 `trtc-wx-sdk` 纯音频进房、收听与退出；
- `live-pusher` / `live-player` 原生组件接线；
- 获得麦权后开启麦克风，松手立即关闭；
- AGC 自动增益与 ANS 基础噪声抑制；
- TRTC 本地网络质量状态；
- 当前占麦人展示；
- 队内位置实时上报。

### 服务端

- 开发态会话；
- 车队创建、加入、退出、查询；
- 在线位置更新与附近距离计算；
- 队内 WebSocket 广播；
- 单房间单麦权租约；
- 45 秒租约过期，避免断网永久占麦；
- 仅向当前车队成员签发短期 TRTC UserSig；
- SecretKey 只从服务端环境变量读取；
- 健康检查和单元测试。

## 明确不包含

- 商用登录、用户实名、风控；
- 头盔蓝牙按键、专用蓝牙路由和耳机兼容性承诺；
- 高速骑行风噪的专项算法或效果保证；
- 后台 / 锁屏操作 PTT 和长期保活承诺；
- 轨迹永久保存和统计；
- 社区、动态、私信、好友关系；
- 运营管理后台；
- 内容审核、举报工单；
- 商店上架、备案和法律文本；
- 生产部署、监控、备份与容灾。

## MVP 验收建议

在两台以上具备实时音视频权限的企业小程序真机上完成：

1. A 创建车队，B 使用房间码加入；
2. 两端成功进入同一个 TRTC 字符串房间并保持收听；
3. A 按住讲话时 B 能听到实时音频，A 松手后上行立即关闭；
4. A 与 B 同时按下讲话时，仅一人获得麦权并发布音频；
5. 占麦者松手后，另一人可在约定时间内拿到服务端麦权；
6. 断网占麦后最迟 45 秒自动释放，客户端网络异常时主动安全关麦；
7. 两端能看到对方队内位置更新；
8. 小程序进入后台、锁屏和系统清理后的行为只记录测试结果，不作为本阶段稳定性承诺。
