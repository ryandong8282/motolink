# MotoLink 首期 MVP 范围

## 目标

用最小成本验证三个核心假设：

1. 摩友是否愿意临时创建 / 加入车队；
2. “按住说话、松手释放”的半双工交互是否适合骑行；
3. 队内实时位置和掉队提示是否具备实际价值。

## 本次实现

### 小程序

- 开发态登录；
- 当前定位、附近车友列表与地图标记；
- 创建车队、使用 6 位房间码加入；
- 车队成员展示；
- WebSocket 连接状态；
- 按住讲话 / 松手释放；
- 当前占麦人展示；
- 队内位置实时上报；
- RTC Provider 抽象与 Mock 实现。

### 服务端

- 开发态会话；
- 车队创建、加入、退出、查询；
- 在线位置更新与附近距离计算；
- 队内 WebSocket 广播；
- 单房间单麦权租约；
- 45 秒租约过期，避免断网永久占麦；
- RTC Ticket 占位接口；
- 健康检查和单元测试。

## 明确不包含

- 商用登录、用户实名、风控；
- 真正的 RTC 音频；
- 后台 / 锁屏稳定性承诺；
- 轨迹永久保存和统计；
- 社区、动态、私信、好友关系；
- 运营管理后台；
- 内容审核、举报工单；
- 商店上架、备案和法律文本；
- 生产部署、监控、备份与容灾。

## MVP 验收建议

在两台以上真机上完成：

1. A 创建车队，B 使用房间码加入；
2. A 与 B 同时按下讲话时，仅一人获得麦权；
3. 占麦者松手后，另一人可在 500ms 内拿到服务端麦权；
4. 断网占麦后，最迟 45 秒自动释放；
5. 两端能看到对方队内位置更新；
6. 小程序退到后台后的行为只记录测试结果，不作为本阶段稳定性承诺。
