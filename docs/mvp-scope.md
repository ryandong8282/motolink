# MVP 范围与验收口径

## 本阶段包含

| 模块 | MVP 能力 |
|---|---|
| 登录 | 开发态手机号登录，返回用户 ID 和开发态 Token |
| 车队 | 创建车队、房间号加入、查看成员 |
| 对讲控制 | 请求麦权、续租、释放、超时自动回收 |
| 实时事件 | 同一车队 WebSocket 广播通道 |
| 位置 | 队内位置点上报与成员最新位置查询 |
| 骑行 | 开始骑行、批量上传轨迹点、结束骑行 |
| 管理端 | 用户数、车队数、骑行数等基础统计 |
| 原生桥接 | iOS/Android 音频会话、前台服务、定位和常亮接口骨架 |

## 本阶段不包含

- 正式短信和微信登录；
- 社区、私信、内容审核、支付；
- 地图底图、路线规划和导航；
- 商业 RTC 音频媒体流；
- 生产推送、电话式离线唤醒；
- 后台长时间稳定率或 300ms 延迟承诺；
- 生产环境安全测评、备案或应用商店审核结果保证。

## 验收用例

1. 两个用户可分别登录，并通过同一房间号进入车队；
2. 用户 A 请求麦权成功时，用户 B 请求得到占用者信息而不是同时成功；
3. A 释放或租约超时后，B 可以取得麦权；
4. 房间内两个 WebSocket 客户端可以收到彼此发送的临时事件；
5. 队员可上报位置，房间成员列表能查询到最后位置及更新时间；
6. 骑行可开始、上传一批轨迹点并结束；
7. 管理端可以显示数据库中的用户、车队和骑行数量；
8. Flutter 页面能完成登录、创建/加入房间和按住说话交互；
9. 原生插件在 Android/iOS 上能响应高层方法，真实 RTC 尚未配置时返回 mock 状态。

## 下一里程碑

在此骨架上，下一步应优先完成“真实双机 PTT POC”，而不是先堆社区页面：

1. 选定一家 RTC 厂商；
2. 服务端生成临时 Token；
3. 两台手机前台半双工通话；
4. Android 锁屏持续收听和前台服务；
5. iOS PushToTalk/后台音频验证；
6. 蓝牙头盔和实车弱网验证。
