# 路线图

## M0：业务骨架（已完成）

- 小程序主要页面；
- 开发态登录；
- 内存版车队、位置和麦权；
- WebSocket 协议；
- 单元测试和 CI。

## M1：腾讯 TRTC 前台纯音频（代码已接线，等待账号真机验收）

- 企业小程序权限验证；
- 服务端动态生成 TRTC UserSig；
- `trtc-wx-sdk`、`live-pusher`、`live-player` 接入；
- 进房默认只收听；
- 获得服务端麦权后开启音频上行；
- 松手、掉线、进入后台和退房时安全关麦；
- AGC / ANS 基础音频处理；
- 网络质量事件展示；
- 两台手机前台对讲验收。

当前 M1 不包含头盔蓝牙按键、专用蓝牙路由、高速风噪保证和锁屏操作 PTT。

## M1.1：真机与弱网验证

- iPhone 与主流 Android 各至少两台；
- 手机麦克风、扬声器和普通耳机；
- Wi-Fi / 4G / 5G 切换；
- 短时断网、异常退出、45 秒麦权回收；
- 5、10、20 人进房；
- 记录首帧可听延迟、卡顿、重连、耗电和腾讯云用量。

## M2：可用的封闭测试版

- 微信登录 + 手机号绑定；
- PostgreSQL 用户 / 车队持久化；
- Redis 麦权与在线位置；
- 轨迹本地缓存及批量上传；
- 队长权限、踢人、解散；
- 基础举报和拉黑；
- 监控、日志脱敏、限流。

## M3：商用准备

- 隐私授权与数据删除；
- 内容审核；
- 管理后台；
- 生产高可用和备份；
- 安全测试；
- 备案 / 上架材料；
- 真实机型矩阵验收。

## 是否转原生 APP 的决策点

完成 M1.1 后，根据真实测试决定：

- 小程序前台对讲是否足够满足目标用户；
- 锁屏 / 蓝牙按键是否成为刚需；
- 后台定位和微信宿主限制是否影响核心体验；
- 用户是否愿意安装独立 APP。

若锁屏对讲、系统级唤醒或头盔物理按键成为硬性要求，应转为 Flutter 业务层 + Swift/Kotlin 原生 RidingCore，而不是继续给小程序打补丁。
