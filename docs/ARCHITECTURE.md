# 架构说明

```text
┌──────────────────────────────────────────────┐
│ 微信原生小程序                               │
│ 登录 / 地图 / 车队 / PTT UI / 位置采集       │
│ live-pusher + live-player + trtc-wx-sdk      │
└──────────────────┬───────────────────────────┘
                   │ HTTPS + WebSocket
┌──────────────────▼───────────────────────────┐
│ Spring Boot API（当前为模块化单体）           │
│ Auth / Team / Location / Floor / RTC Ticket  │
│ 服务端生成短期 TRTC UserSig                  │
└──────────────┬───────────────────┬───────────┘
               │                   │
         PostgreSQL/PostGIS      Redis
         用户/车队/轨迹          在线位置/麦权/会话
               │                   │
               └─────────┬─────────┘
                         │
                 腾讯云 TRTC 音频房间
```

## 为什么首期不拆微服务

MVP 的核心风险不是单机吞吐量，而是产品交互、小程序平台权限、真机音频表现与弱网体验。先做模块化单体可以：

- 保持部署和排障简单；
- 让车队、位置、麦权事务边界清楚；
- 等到真实并发与成本数据出现后再拆分；
- 避免为了“架构好看”提前引入消息队列和分布式一致性。

## 实时通道

### HTTPS

用于登录、创建 / 加入车队、获取房间快照、附近查询和 RTC Ticket。

RTC Ticket 由服务端按当前登录用户和车队成员身份签发，包含：

- `sdkAppID`；
- `userID`；
- `strRoomID`；
- 短期 `userSig`；
- 过期时间。

TRTC SecretKey 只存在于服务端环境变量，不能进入小程序包、前端配置或日志。

### WebSocket

用于：

- 队员加入 / 离开；
- 精确位置更新；
- 抢麦请求与释放；
- 心跳和连接状态；
- 后续掉队提醒、队长广播。

### TRTC

TRTC 只负责低延迟音频媒体传输。麦权仍由 MotoLink 服务端决定，不能仅依赖客户端静音按钮，否则多端竞争时会串麦。

当前半双工链路：

```text
用户按下按钮
  -> WebSocket 请求 FLOOR_REQUEST
  -> 服务端原子授予唯一麦权
  -> 客户端收到 FLOOR_GRANTED
  -> TRTC 打开本地麦克风上行
  -> 用户松手或页面进入后台
  -> 立即关闭上行并发送 FLOOR_RELEASE
```

所有成员进入房间后持续订阅远端音频，但默认关闭自己的麦克风。这样不必在每次按下按钮时重新进房，减少首帧延迟。

## 小程序音频边界

当前版本只验证手机麦克风和手机扬声器 / 普通系统音频路由：

- 不实现头盔物理按键；
- 不承诺特定头盔蓝牙协议兼容；
- 不承诺锁屏状态下可继续按键讲话；
- 页面进入后台时主动关闭本地音频上行并释放麦权；
- 真机音质、延迟、弱网恢复和后台收听行为必须用企业小程序账号验收。

## 数据隐私原则

- 附近陌生人：只返回距离及模糊坐标；
- 同队骑行：在用户主动加入并开启共享后才广播精确坐标；
- 位置设置短时有效期，过期不展示在线；
- 服务端日志避免记录原始精确经纬度；
- 生产环境需要用户可撤回授权、删除轨迹和注销账号；
- 麦克风仅在获得麦权且用户持续按住时开启上行。
